## Deviations log
- `/#cv`: treated as a deep link (skips the intro, opens the CV directly), matching the acceptance checklist's `extra-intro-21` decision and the orchestration log below. Only a known sheet id (`#cv`, `#crumbify`, `#racing`, `#video`, `#about`) skips the intro. An unknown hash such as `/#bogus` plays the normal intro. The inline pre-hydration script and usePile share one definition (orchestrator decision 2026-09-23, review round 2).
- Font CSS custom properties (`--font-sans`/`--font-mono`/`--font-serif` in `globals.css`) are applied via a `className` on `<html>` rather than `<body>`. `next/font`'s variable classes (`--font-plex-sans` etc.) were originally on `<body>`; since `--font-serif` is declared on `:root` (`<html>`) and references `var(--font-source-serif)`, and CSS custom-property `var()` substitution resolves once at the *declaring* element (not lazily per-consumer), the reference was guaranteed-invalid at `<html>` and the empty result inherited down, silently falling back to the browser's default serif everywhere. Moving the `next/font` variable classes to `<html>` (same element as the alias tokens) fixes this; confirmed via `getComputedStyle` before/after and a visual screenshot diff against the reference.
- Racing GPS polaroid crop (corrected 2026-09-24, review round 4 slice-rv-gps-crop-01): the reference stores this crop as `scale 1.8, offset x +18%, y +50%` (`design_handoff_alibars_portfolio/reference/.image-slots.state.json`), applied by its image-slot web component's own `_applyView` method (`reference/image-slot.js`, ~lines 1000-1060): the image is sized to `cover` the frame at `scale`, and its centre is pinned to `(50+x)%`/`(50+y)%` of the frame via an absolutely positioned `<img>` with `transform:translate(-50%,-50%)` — not `object-fit`/`object-position`, which cannot express an off-centre pan once the image is scaled (`object-position`'s x axis has no effect once `cover` has already stretched that axis to fill the frame). The earlier note above (superseded) blamed the literal offset numbers for a wrong crop and substituted a hand-tuned `object-position`/`scale` pair instead; the actual bug was reproducing the wrong CSS mechanism, not the numbers. `src/lib/imageSlot.ts` now reproduces `_applyView`'s formula exactly (verified against the reference's asset dimensions, 161x348px, in `src/lib/imageSlot.test.ts`), and `RacingSheet.tsx` renders it via an absolutely positioned `<img>`. The asset itself is still the low-res placeholder flagged in the handoff; revisit once Ali supplies a higher-res original.
- Sticky note is a child of the `.stage` grid (not the outer `stageWrap`), so its `position:absolute` anchors to the actual pile box. It was previously a sibling of the responsive mobile tab row, which — being out of normal flow — stayed pinned near the top of `stageWrap` and got hidden behind the tab bar at <600px once tabs moved into flex flow. Fixed by nesting it inside `.stage`, which itself moves down under the tab row on narrow viewports. At very narrow widths (down to 390px) the note (210px wide) still visually overlaps part of the CV name/tagline, which reads as intentional given the "sticky note stuck on the page" metaphor and matches the corrected z-order in a screenshot check.
